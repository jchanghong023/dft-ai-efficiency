# FAQ / 最佳实践

## 页面离线能用，为什么模型不能回答

门户完全离线；客户端只是离线分发，推理仍依赖已配置且目标网络可达的模型服务。门户不会替你配置服务或下载模型。

## 同步找不到二进制或发现 LFS 指针

Git 获取的代码可能只有 LFS 指针。外围运行 `git lfs pull`，或使用携带实体的离线包。同步与打包直接检查实体的 ELF 格式及架构，不会把指针当成可执行文件。发行方 SHA-256 在下载更新时核验；打包另核对复制前后的实体哈希。

## 同步报告 WAL / SHM / journal 未关闭

不要直接删除 sidecar 强行继续。让数据库维护者停止写入，完成 SQLite checkpoint 并正常关闭连接，再导出或复制完整一致的主数据库。脚本不合并运行中的数据库。

## yellow/docs.db 缺失会怎样

跳过并保留个人数据库；不会创建空数据库替换它。原始 Markdown 仍留在仓库里，公共门户与公共包只保留 `yellow/.gitignore`。

## OMP 进程无法退出

若最初停止 OMP 进程失败，同步尚未开始覆盖；查明当前任务或权限问题并手工正常退出后重试。脚本只处理当前用户进程，不操作其他用户的 OMP。若同步中重新启动进程，脚本会中止后续替换，但此前已输出 `UPDATE` 的变更不会自动回退。

## Skill 或 Worker 没有出现

检查实际 profile、`omp config path`、Skill 启用设置及同名项目覆盖。此同步只负责默认 `~/.omp/agent/`。重新启动 OMP，或对扩展改动使用 `/reload-plugins`；在 `/extensions`、`/agents` 查看来源。

## Wiki 无结果或源路径失效

先用 `omp docs list` 确认索引，多个索引需指定名称。再使用团队上下文中的原始资料路径 read/grep。旧索引可能保留建库机路径；同步不会擅自重写索引内容。必要时由公司维护者按真实目录重新建库。

## 内部文档是否进入公共页面或发布包

不会。顶部“内部文档”读取本地生成的 `yellow/.site/`，左侧按 `yellow/docs/` 的 Markdown 文件导航。公共页面、公共全文索引和公共发布包不包含内部正文或文件名。默认构建会更新内部页面；`--public-only` 只构建公共部分且不访问黄区。公司 Markdown、附件、数据库和内部生成页面不能进入公共 Git。

## 生成基础电路是否表示 Sailor 已通过

不表示。基础 RTL、语法检查、功能仿真、真实 PAD 接入、DFT 插入验证是不同完成层次。缺 PAD 库或 Sailor 时只报告已完成的层次，不虚构工具命令或成功日志。

## 怎样写一个有效开发需求

明确目标模块、预期输入输出、要保留的接口、可用测试及资料位置。使用 `/code-and-verify` 后检查实际 diff 与验证证据；不要用“Agent 说通过”代替退出码和结果。

## 如何更新门户版本

更新二进制只运行 `python3 scripts/maintenance/maintain_binaries.py`。门户内容按需单独维护，修改公共正文和命令说明后重新构建即可；手册参考版本不与二进制绑定。普通离线构建不联网。详见[维护与版本](maintenance.html)。
