# LBIST：LFSR 激励、MISR 签名与混叠

LBIST（Logic Built-In Self-Test）把逻辑测试所需的一部分激励和响应比较结构放进芯片。常见教学框图是 PRPG/LFSR 产生伪随机模式，扫描链或组合逻辑产生响应，再由 MISR 压缩成一个签名。芯片只需比较最终签名是否等于已知的无故障签名，但签名相同并不证明所有内部响应都相同。

LBIST 的“自测”仍然依赖设计约束：测试时钟、复位、扫描链控制、屏蔽未知值和比较时点都需要在工程中定义。本页把这些边界留在说明文字中，不把小模型包装成插入工具或硅后测试结果。

## 四个概念先对齐

| 概念 | 作用 | 本页约定 |
|---|---|---|
| LFSR | 由线性反馈产生可重复的伪随机状态序列 | 4 位、非零种子 0001、固定多项式位序 |
| 激励 | 将 LFSR 状态施加到待测逻辑 | 直接把 4 位状态送进教学 DUT |
| MISR | 将每拍响应累积到多位寄存器 | 4 位、逐位 LSB-first 更新 |
| 签名 | 测试结束时的压缩状态 | 只与本页固定序列比较 |

## 动手观察一个已知序列

## 多项式和位序不能含糊

本例的 LFSR 采用向量 `[b3 b2 b1 b0]`：每拍变为 `[b2 b1 b0 (b3 XOR b2)]`，所以新 bit0=`old b3 XOR old b2`；若把输出序列记为 `y[t]`，可得 `y[t+4]=y[t+1] XOR y[t]`，对应特征多项式 `x^4 + x + 1`。MISR 是独立的固定教学压缩递推，不声称与 LFSR 使用同一硬件多项式：对响应的 bit0 到 bit3 依次处理，令 `f=s3 XOR input`，先左移为 `s=[s2 s1 s0 0]`，再在 `f=1` 时 XOR `0011`。也就是说，反馈位不是直接 OR 进最低位；例如从签名 `0000` 注入响应 `0001` 后，四个串行输入位的结果是 `1011`，最低位可以为 1。换一种寄存器画法、移位方向或输入位序，得到的数值就会改变；工程规格必须明确这些约定。

如果把最高位改成最低位反馈、把响应从 bit3 开始输入，或采用 Galois 而不是 Fibonacci 结构，序列和签名都会不同。页面显示的 `0001 → 0010 → 0100 → 1001` 是当前实现的已知序列，不是所有 LFSR 的通用答案。

## 签名比较和混叠

不同响应序列可能经过线性压缩后得到相同签名，这叫 aliasing（混叠）。因此签名比较是筛选机制，不是逐位保留的证据。真实 LBIST 还需要考虑 X 值、时钟控制、测试点、功耗、随机难测故障和诊断需求。本页没有计算或宣称真实覆盖率、混叠概率、测试时间收益或安全等级。

为了让边界可复现，故障选项只钳位教学 DUT 的 response bit1。它没有改变 LFSR 或 MISR，也没有模拟 X 值、时钟竞争、功耗下降或布局布线寄生；这些内容需要真实网表、约束和仿真环境。

## LBIST 与确定性 ATPG 的边界

ATPG 根据指定故障模型寻找确定性模式和期望响应；LBIST 依靠芯片内伪随机序列，硬件开销和模式数、随机难测故障之间需要权衡。实际流程可能组合 LBIST、压缩扫描、测试点和确定性补充模式，不能把本页的 8 拍示例当成完整制造测试方案。

### 看结果时问三个问题

- 使用的种子、位宽、抽头和输入位序是否相同？
- 比较的是最终签名，还是逐周期的原始响应？
- 失败是否需要诊断、补充 ATPG 模式或测试点，而不只是重跑随机序列？

这三个问题能避免把“签名不一致”直接等同为某一个物理缺陷，也避免把“签名一致”误解为穷尽了所有故障。
