# MBIST、BIRA、BISR：测试、分析、修复分成三步

MBIST（Memory Built-In Self-Test）把存储器访问序列放进芯片内的测试控制器。它可以在生产测试或系统启动时，对嵌入式 SRAM 等存储器施加读写操作，并记录失败地址；但“发现失败”和“修好存储器”不是同一个动作。

## 先分清三个角色

| 模块 | 负责什么 | 本页模型做什么 |
|---|---|---|
| MBIST | 生成地址顺序与读/写操作，比较读回值 | 逐步执行一个简化 March 程序 |
| BIRA | 根据失败地址分配可用的冗余行/列 | 用贪心规则把失败行映射到 spare row |
| BISR | 保存并加载修复信息，使后续访问绕过坏行 | 把映射加载到模型，再跑验证读写 |

真实芯片还会包含存储器接口、控制器时序、诊断寄存器、熔丝/OTP 或其他非易失配置路径。本页只展示数据关系，不能替代工艺库、宏模型或供应商的修复流程。

### 读图时看三条路径

1. 左侧是 MBIST 发出的逻辑地址、操作和期望数据。
2. 中间是逻辑行到物理行的当前映射；没有修复时，两侧地址相同。
3. 右侧是 BIRA 的资源判断和 BISR 的映射加载状态。

“当前值”是教学模型在本拍后的值；它不是 SRAM 宏内部的晶体管状态，也没有模拟读写延迟、保持时间或电源噪声。

## 动手跑一个简化 March 测试

选择故障后点击“单步”，每一步只执行一个地址操作。网页交互固定使用 8 行、地址 0 到 7；JavaScript 纯模型 API 另外允许正整数行数，用于单元测试和扩展示例。默认在地址 3 注入一个 stuck-at-1 故障。测试程序按“升序写 0、升序读 0 写 1、降序读 1 写 0、降序读 0”展开。读操作才会产生比较失败，写操作只改变模型中的存储值。

当读 0 却得到 1 时，控制器只知道“某个地址在这个操作下不符合期望”；真实诊断可能还要区分 stuck-at、transition、coupling 或地址译码故障。这里的故障地址是教学输入，不是工具诊断结果。

### 一个失败如何被记录

| 观察 | 控制器记录 | 后续用途 |
|---|---|---|
| `R0` 读出 `1` | 地址、期望值、实际值 | 形成失败地址集合 |
| 同一地址再次失败 | 不重复增加资源需求 | BIRA 对地址去重 |
| 不同地址失败 | 需要不同的冗余映射 | 与 spare 数量比较 |

因此演示中地址 3 可能在多个读 0 操作中失败，但 BIRA 只需要为这一行分配一次 spare。量产工具还可能记录行列信息、失败类型和诊断上下文。

## 为什么 BIRA 需要资源分配

冗余行不是无限的。BIRA 先把失败地址去重，再从有限的 spare rows 中分配映射。本演示的一条 spare row 足以修复一个失败行；如果同时注入地址 3 和 6 两个坏行，第二个地址没有资源，BIRA 会明确标为未修复，而不会报告“全部通过”。实际 BIRA 可能使用更复杂的行列联合分析、冗余约束和修复优先级。

如果坏的是列而不是行，简单的“一个地址换一条 spare row”模型就不适用；如果冗余结构共享，也不能仅按失败地址数量判断可修复性。这里专门固定为行冗余，让资源耗尽的边界可以被单步观察。

## BISR 的加载时点

BISR（Built-In Self-Repair）不是重新执行 MBIST。它把 BIRA 形成的修复映射装入修复寄存器或相关配置路径，之后地址译码把逻辑地址重定向到 spare row。制造流程中，修复信息可能写入 eFuse、OTP 或其他非易失介质，并在上电时加载；本页只模拟“加载映射”，不操作真实熔丝，也不声明永久修复。

验证阶段重新写入 0/1 并读回。只有验证操作通过，模型才显示“修复后通过”；如果 spare 不够，剩余坏地址会继续失败。

验证不是“擦除故障”，而是检查地址重定向后逻辑接口是否仍然表现正确。演示把 spare 初始化为普通可读写单元；真实宏还要验证修复后的地址译码、冗余选择、启动加载顺序和不同测试模式之间的切换。

## 故障模型和覆盖率边界

本页的 stuck-at-1 是人为注入的单一逻辑模型。一次已知序列通过，只说明该序列下的模型观察到预期行为，不是 memory fault coverage、良率或量产测试结论。March 算法的具体元素、读写方向、时序和故障覆盖能力需由存储器类型、工艺和验证目标决定。

### 不要把三个结果混为一谈

- **测试失败**：某个操作的实际读回值与期望值不同。
- **可修复**：BIRA 找到足够的行/列冗余，并形成合法映射。
- **修复后通过**：BISR 加载映射后，验证操作没有留下失败。

一个设计可能测试失败但可修复，也可能测试失败且冗余不足；只有最后一种验证结果才允许在本模型中显示 `PASS`。
