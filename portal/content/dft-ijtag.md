# IJTAG：让片内仪器按需接入

IEEE 1687（通常称 IJTAG）关注的是片内嵌入式仪器的访问网络。它把“网络如何连接”和“仪器如何操作”分开描述，并支持把面向仪器的操作重新定位（retarget）到当前芯片可执行的扫描序列。

> **范围声明**：本页的 SIB、链长和位序列是一个单段教学模型，不是任何 EDA 工具的实现，也不产生真实的 ICL/PDL 文件、ATPG 模式或仪器测量结果。

## 为什么需要动态路径

如果所有 MBIST、传感器、调试寄存器永远串在一条链上，普通的访问会变长、测试时间增加，也更难隔离未使用的仪器。IJTAG 用可控的段插入位（SIB）决定一个数据段是否进入当前扫描路径：

```text
TDI → SIB=0 → 旁路位 → TDO
TDI → SIB=1 → 目标仪器寄存器 → TDO
```

真实网络可能有多个嵌套 SIB、并行段和不同层级的访问寄存器；访问协议仍需要遵守具体实现的扫描时序。

## ICL、PDL 与 retarget

| 名称 | 回答的问题 | 在流程中的位置 |
| --- | --- | --- |
| ICL（Instrument Connectivity Language） | 哪些仪器、寄存器、SIB 和端口如何连接？ | 描述结构与可达路径 |
| PDL（Procedural Description Language） | 如何复位、写入、触发、读取某个仪器？ | 描述仪器操作意图 |
| Retarget | 如何把仪器级操作映射到芯片顶层扫描入口？ | 根据当前 SIB 配置生成访问序列 |

因此，PDL 中“写入某寄存器”不是直接对 TDI/TDO 的魔法调用。工具需要结合 ICL 找到路径，插入打开 SIB 的操作，完成数据寄存器扫描，再按需要关闭或保留路径。没有 ICL/PDL 和对应工具链时，不应声称已经完成 retarget。

## 动手改变链长

交互默认关闭 SIB，完整当前路径只有一位 SIB；先用 `Shift SIB 位` 准备控制位，再用 `Update SIB` 提交开闭，选择的仪器段才会插入扫描路径。打开后，`Shift 完整路径` 同时经过 SIB 与仪器寄存器，`Update 仪器值` 才提交仪器段。`Memory BIST` 示例为 8 位仪器段，`温度传感器` 示例为 4 位；SIB 关闭时的移位不会改变仪器值。

### 读懂一次访问

可以把一次访问拆成四个动作：先复位网络，再把 SIB 控制位移到目标值；接着在段已插入的路径中扫描仪器寄存器；最后按仪器定义的顺序更新或读取。每一步都可能有额外的 Capture、Update 或等待周期。

在多级网络中，外层 SIB 打开后，内层 SIB 才可能被看到。关闭外层段会让内层路径暂时不可达，但不代表内层仪器丢失配置；具体保持还是复位同样由实现定义。

## 设计时要注意什么

- **复位与默认路径**：SIB 上电值、系统复位和测试复位必须明确，否则工具可能访问到错误的层级。
- **链长变化**：打开段后，后续位的位序和总长度都改变；模式生成必须使用当前网络配置。
- **X 与副作用**：未初始化仪器、时钟域和模拟输出可能产生未知值，不能只用理想 0/1 推断硅上结果。
- **可复用性**：块级 ICL/PDL 需要在芯片级重定向后验证，嵌套网络的命名和端口映射必须保持一致。

## 与 JTAG 的关系

IJTAG 描述的是片内仪器网络和访问抽象；JTAG/1149.1 是常见的外部串行入口之一，但不是 IJTAG 的全部。一个芯片也可能通过其他测试控制器或调试入口访问片内仪器。不要把 SIB 当作 TAP 的第 17 个状态，也不要把 PDL 当作测试向量覆盖率报告。
