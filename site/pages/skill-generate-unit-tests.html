generate-unit-tests

用途

从当前实际代码修改出发，复用目标项目既有测试框架，补充并执行相关单元测试，输出可核实的验证结果。

适用与不适用

适用于功能修改、缺陷回归、受影响边界条件和跨模块契约的验证。不适用于只读代码审查、无关覆盖率提升、另建测试框架，或把当前项目迁移到另一套运行器。

如何调用

Agent 可自动选择：是。必须手动调用：否。也可显式调用：

/skill:generate-unit-tests 对当前未提交的复位修改补充相关 UT，并执行项目已有测试入口

输入

用户指定的变更范围、真实 diff、受影响代码、项目规则、现有测试和构建/CI 运行入口。遇到暂存和未暂存修改时一并识别，但只处理本任务相关部分。

输出

相关测试及必要 fixture 的变更；实际运行命令、退出码、通过或失败结果；必要日志位置和未验证项。测试验证可观察行为，不能仅检查与实现同构的内部细节。

示例与缺失条件

已有 pytest 项目时沿用配置和 fixture，针对当前行为修改测试并运行相关用例，而非新增一套自制断言框架。缺少测试框架时先查构建与 CI；仍无法确定时输出测试设计和缺口，不宣称测试已经通过。

硬件仿真器、库或公司工具缺失时区分“用例已写”和“运行已验证”。失败用例不得通过降低断言或无关产品代码修改来掩盖。

参阅统一开发命令与验证边界。

# 补充相关单元测试

读取用户指定范围的实际 diff、受影响行为、已有测试和运行器配置；存在暂存与未暂存修改时都检查，但不把无关改动纳入任务。

复用目标项目的框架、fixture、mock 边界和命名习惯。用可观察输入输出或契约验证变更，优先原始缺陷回归、正常路径和受影响的关键边界；不要按实现结构逐句镜像断言。对缺陷修复，在可行且不污染工作区时证明用例能区分修复前后行为。

执行对应的已有测试入口和项目强制检查。跨模块契约变化时按需运行已有集成测试，不擅自另建测试框架。找不到框架时先查构建/CI 脚本和项目文档；仍缺少必要运行条件，则列明缺口，交付可确定的测试设计，不声称测试通过。

只为本次行为增补必要用例与 fixture，不修改产品代码掩盖失败，不降低既有断言。执行输出归入目标项目允许的临时目录；新 Python 验证入口使用 Python 3.11+。

交付相关测试变更、实际命令、退出码及测试结果，并说明未验证部分。可自动选择，也可通过 `/skill:generate-unit-tests <修改范围>` 显式调用；无须强制手动调用。
