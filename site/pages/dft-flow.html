    完整的 DFT 交付不是“插入工具跑完”这一条命令，而是一条有证据闭环的工程链：先定义测试目标与约束，再插入结构、验证结构和功能，最后生成、仿真并带到 ATE。下面把每个阶段的输入、输出、常见失败与下一步放在同一张地图上。

    流程总览

    阶段 关键输入 可交付输出 失败时先看什么
    规格与库准备 测试目标、工艺库、RTL、时钟/复位约束 DFT 规格、库能力清单、约束基线 是否有真实 scan FF、测试时钟和 PAD 资料
    模式规划 链数、外部通道、功耗、模式与层级边界 test mode 表、链路/时钟规划 模式之间的互斥、复位释放和功耗预算
    DRC RTL、库模型、约束、模式规划 DFT DRC 报告及豁免依据 时钟、复位、异步控制、不可控/不可观节点
    结构插入 通过的 RTL/网表、库单元、规划 插入后的 RTL/网表、约束和日志 插入版本、库映射、黑盒和命名变化
    结构/等价/连接验证 插入前后设计、约束、形式/仿真环境 结构报告、等价报告、链连接报告 逻辑差异、链顺序、test mode 覆盖
    ATPG 故障模型、插入网表、时序/模式约束 pattern、预期响应、覆盖率与未测原因 故障激活/传播、约束冲突、X 来源

    Pattern simulation pattern、SDF/时序模型、ATE 约定 时序仿真波形、协议与功耗证据 launch/capture 边沿、setup/hold、X 传播

    交付物的最小闭环

    • 设计快照：RTL/网表、库版本、约束、模式表和工具版本必须可以相互追溯。
    • 结构证据：链数量、每条链的首尾、寄存器顺序、时钟/复位连接和豁免列表。
    • 模式证据：每个 pattern 的输入、期望响应、压缩映射、功耗/频率限制和生成日志。
    • 仿真证据：无故障、故障、门级时序三类结果，注明模型、SDF、频点和 X 策略。
    • 硅上证据：ATE 通道映射、失效 cycle、温压频点、复测结果和诊断范围。

    缺少其中一类证据时，应把状态标记为“待确认”，而不是用另一类报告代替它。尤其不能用 ATPG 覆盖率代替 RTL 功能验证、结构等价或硅上质量判断。

    每个阶段怎样留下证据

    1. 规格、库、时钟与复位

    先写清要测什么：制造故障、速度故障、存储器，还是板级互连。收集真实工艺库中的 scan flip-flop、锁存器、测试时钟单元、隔离/电源域单元和 PAD/边界单元；同时确认库模型、时序弧、test enable 极性与可用电压域。没有这些资料时，只能做规划，不能宣称完成真实单元接入。

    输入是 RTL、库与工艺资料、时钟/复位约束、功耗和 ATE 限制；输出是版本化的规格、库能力清单、mode/clock/reset 表。常见失败是只拿功能仿真约束运行测试流程，遗漏异步复位、门控时钟或多电源域。下一步应补齐缺失证据，再进入 DRC。

    至少应记录以下问题：

    • 哪些寄存器可替换为 scan 单元，哪些状态必须保留或旁路？
    • shift、capture、测试复位与功能复位分别由哪个时钟和控制信号驱动？
    • 测试时的电源域、隔离和电平转换条件是否有真实库模型？
    • PAD、边界单元和 ATE 电气限制是否已由项目资料确认？

    2. 模式规划与 DRC

    把功能模式、shift、capture、MBIST、JTAG/IJTAG 等模式的控制信号、时钟来源、复位策略、隔离策略和允许的组合写成表。DRC 用来发现结构不可测、控制冲突和不安全的测试路径；每个豁免都应有设计依据和责任人，而不是把告警改成通过。

    DRC 输入为带约束的设计和规划，输出是可追踪报告。若出现 reset 未约束、clock gate 不可控、scan enable 在捕获时错误翻转等告警，先定位控制路径和模式条件；不要直接删告警或猜测工具默认值。通过 DRC 只表示规则检查有证据，不表示覆盖率或硅上测试已完成。

    DRC 结果应按“错误、警告、已审豁免”分组保存，并为每条豁免记录影响范围。模式表还应覆盖：

    • shift 时允许的时钟、复位、test enable 和隔离状态；
    • capture 时 launch/capture 脉冲的来源、边沿与频点；
    • 多时钟域之间的锁存、跨域和 lockup 处理；
    • 低功耗模式下哪些测试结构必须保持可控或被安全旁路。

    3. 插入与结构验证

    使用已批准的工具流程和真实库执行插入，保存输入快照、版本、参数、日志和输出网表。插入后要检查 scan chain 数量、长度、锁存/分组、时钟和复位连接，并做插入前后的功能等价或约定范围内的比较。结构连接验证应能回答“每条链从哪里进、经过哪些寄存器、从哪里出”。

    常见失败包括链顺序和约束不一致、黑盒导致等价失败、测试控制没有覆盖全部层级、插入改变了不允许改变的功能路径。先比较结构报告、端口映射和差异锥，再决定是修复约束、库映射还是设计；不要编造某个具体工具的命令或成功日志。

    结构验证至少要回答四个可复现的问题：

    1. 插入前后功能端口和允许变化的测试端口是否一致？
    2. 每个 scan cell 的 SI、SO、SE、D 和 Q 是否落在预期时钟域？
    3. 结构报告中的链长与模式仿真实际移位位数是否一致？
    4. 任何失败能否从输入快照、日志行和报告版本定位，而不是依赖口头描述？

    4. ATPG 与两类仿真

    ATPG 的输入是经过验证的插入设计、故障模型、时钟/复位/测试约束；输出是测试模式、期望响应、故障覆盖和未测原因。ATPG 覆盖率描述所选故障模型在约束下被检测的程度，不能替代 RTL 功能验证，也不能直接等同于真实制造质量。

    Fault simulation 验证模式对故障模型的检出分类；Pattern simulation 则进一步检查无故障门级/时序模型上的模式协议、X、setup/hold、launch/capture 和功耗条件。若两者冲突，先确认网表、库、模式版本和时钟复位条件完全一致，再比较波形与期望响应。

    阅读覆盖率报告时，应把故障分成已检测、未检测、不可测、受约束和不可模拟等类别，并保留分类原因。一个模式把某个 stuck-at 故障激活并传播出来，只能说明这个故障在该模型和该约束下被观察到；它不证明 transition、bridging 或工艺特有缺陷也被覆盖。

    Pattern simulation 的顺序通常是先确认协议，再确认数据：先看 test mode、复位、时钟和比较窗口，再看每条链的位序、压缩响应和 X。这样可以避免把通道映射错误误诊为逻辑故障。

    5. ATE、bring-up 与 diagnosis

    把签核后的模式转换为经过审查的 ATE 格式，核对通道、极性、时钟、比较窗口、电源和压缩数据映射。bring-up 先做低风险的链路、IDCODE/旁路或已知响应检查，再逐步打开目标模式；首片失效要保存 tester 日志、温压频点、失效 cycle、链/通道位置和复测结果。

    Diagnosis 是基于证据缩小候选范围，不是把第一条失败链当成根因。将仿真响应、ATE bitmap、失效模式和版图/时钟区域交叉比对，区分测试程序、封装/接触、电源时钟、结构缺陷和真实逻辑问题。任何教学结论都不能替代公司工艺、ATE 或硅上数据。

    首片 bring-up 的记录建议包括：

    • tester 程序、pattern 集合、通道/极性映射和加载时间；
    • 电源、温度、频率、复位和时钟条件；
    • 首次失败与复测失败是否在同一 cycle、同一链或同一通道；
    • 是否能用旁路、低速或已知响应模式把问题缩小到接触、时钟、模式或设计。

    互动排障：先取证，再推进

    演示包含四个独立构造的小模型，结果由输入条件计算，不读取真实网表或预先写好的“通过”日志。修改条件会清除旧证据并重算表格；每一步先检查、后推进，取证结束仍保留异常或无法判定的项目。

    场景 可调整条件 观察与边界
    四级扫描链 Q2→Q3 正常/固定零断点，三组刺激 八个沿的移入/移出记录；0000 可能掩盖断点，另用 1111 交叉检查。只模拟固定零断点，不模拟悬空节点电气行为
    两域同步复位 约束是否记录、B 域复位释放沿 D 均为 1，在第 2 沿比较响应；“已写约束”不自动释放真实复位。模型不验证异步复位 recovery/removal
    XOR 的 X 传播 源值、mask、A stuck-at-0 X 传播到输出；mask 只放弃该点比较，不消除 X、不修复故障。未知或屏蔽均不能报告通过
    单路径捕获 数据延迟、周期、setup、脉冲数 计算 周期 − setup − 延迟；缺捕获沿或负裕量不能宣称确定采样值。无 skew、hold、库时序弧或亚稳态仿真

    建议分别尝试“断点 + 全零刺激”“已记录约束 + 复位晚释放”“注入故障 + 屏蔽观察点”“裕量为正 + 缺捕获脉冲”。这些组合说明：单项检查看似正常，不代表整个测试条件成立。再改变造成缺口的条件，比较重新计算出的证据。

    可复用的排障顺序

    1. 固定输入版本：RTL/网表、库、约束、模式和工具日志必须能互相对应。
    2. 从最靠近症状的可观测证据开始：链路看连接，复位看释放条件，X 看来源，时序看边沿和约束。
    3. 每个结论记录证据、反证和下一步；未检查的假设保持未确认。
    4. 修复后重跑受影响的结构、等价、仿真和模式检查；不要只看一项报告变绿。
