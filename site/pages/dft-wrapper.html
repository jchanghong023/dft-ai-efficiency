Wrapper 与分层 DFT：隔离、串接、复用

ACCESS LAB · 03

Wrapper：让层级测试各走各的路径

在一个可复用核周围，Wrapper Cell 可以隔离核心、串接边界或旁路。切换模式观察同一输入如何到达核心与输出；它与芯片 PAD 上的 Boundary Scan Cell 是相关但不同的工程结构。

Internal Test 把测试刺激送入核内部，外部边界保持安静；External Test 通过外部 Wrapper 观察或驱动核边界；Bypass 绕过核心，适合层级串接。

大型 SoC 往往先分别验证可复用核，再把多个核集成到芯片。Wrapper 是围绕核的测试结构：它可以把内部测试数据送到核边界、观察外部连接，也可以在不访问核内部时直接旁路。这样做的核心是控制测试边界，不是把一条普通功能总线换个名字。

范围声明：本页交互只展示三种数据路径的逻辑关系。实际 Wrapper Cell 数量、控制信号、时钟域、协议和插入结果必须由目标工艺库、核交付物与 DFT 工具共同确定。

三种层级模式

模式 数据路径 目的
Internal Test 测试端口 → 边界 Cell 的内测角色 → CORE → 边界 Cell → 测试端口 在隔离外部连接的条件下测试核内部
External Test 测试端口 → 边界 Cell 的外测角色 → 简化互连 → 边界 Cell 捕获 → 测试端口 观察/驱动外部互连；核心逻辑保持隔离
Bypass 测试端口 → 旁路通路 → 测试端口 不访问当前核，缩短分层访问路径

点击“应用数据路径”再观察核心与输出，模式改变后先不会自动宣称结果，提醒读者区分“选择控制”与“实际时钟更新”。

Wrapper Cell 做什么

一个常见的 Wrapper Cell 可能包含并行捕获、移位寄存器、更新寄存器和多路选择控制；同一组边界 Cell 可以在模式控制下复用为内测角色、外测角色或旁路角色，并不意味着工艺库里固定存在两种名为“内部/外部”的单元。内测时，边界 Cell 可以把芯片级信号隔离，避免外部未知值污染核测试。外测时，它可以把核边界暴露出来，支持核间互连测试。旁路时，访问链越过当前核，继续到下一个层级。

这些是逻辑意图，不等于某个工具已经插入了单元。实现阶段仍需要 DFT 规则检查、时序/功耗约束、模式仿真和与核交付的端口映射。

模式切换不是瞬间完成

工程里通常要在测试控制器的规定时刻更新模式位，再经过必要的时钟沿让多路选择器和寄存器生效。切换期间还要处理输出使能，避免两个来源同时驱动同一网络。交互将“选择模式”和“应用数据”分成两个动作，帮助区分控制寄存器更新与数据传播。

当核包含多个时钟域、异步复位或低功耗电源域时，Wrapper 的隔离值和更新时机更需要单独约束。只看理想 RTL 的 0/1 路径，不能替代门级仿真、STA 或硅上测试。交互的 External Test 只计算外部 link(input)（可选正常、反相或固定故障）并由边界 Cell 捕获，不把 CORE 的反相功能冒充成外测结果。

Wrapper 与 Boundary Scan 不同

二者都可能拥有捕获、移位和更新等结构，所以容易混淆：

对象 主要位置 主要服务对象
Wrapper 可复用核的边界、层级集成接口 核级内测、外测、旁路和层级复用
Boundary Scan Cell 芯片 I/O PAD 附近的边界寄存器 芯片/板级引脚与互连测试

JTAG TAP 可以成为二者的访问入口，但 TAP、Wrapper 和 Boundary Cell 是三个不同层次的概念。芯片可能把多个结构串进同一测试链，也可能使用其他控制网络。

集成时的检查清单

  1. 核的测试端口、时钟、复位和 Wrapper 控制是否在顶层有明确连接？
  2. Internal/External/Bypass 的优先级是否没有造成组合环路或不受控驱动？
  3. 多个核串接时，旁路长度、位序和更新时机是否与模式生成配置一致？
  4. 隔离值是否满足低功耗电源域和上电顺序要求？
  5. DFT DRC、门级模式仿真和必要的 STA 是否覆盖了这些模式？

一个常见误区

“加入 Wrapper”不等于“核已经可测”。可测性还依赖内部状态的可控/可观测程度、扫描链、时钟控制、约束和 ATPG。反过来，Boundary Scan 也不能替代核内部的测试结构；它主要提供外部边界访问。
