# 生成 DFT 插入前电路

先确认用户目标工程、输出路径、现有 HDL/验证工具和指定资料。默认规范见 [tiny-base.md](references/tiny-base.md)；用户明确给出的接口或层级优先。输出到目标工程，不在效率仓库创建电路案例。

从用户工程和指定库资料识别真实 Input/Output PAD 单元、方向、端口、电源与使能连接要求以及仿真模型。缺少信息时明确列出缺少的单元/端口/模型。可完成与工艺无关的核心 RTL 和测试；未接 PAD 的逻辑版必须标为未接真实 PAD，不用虚构单元或假工艺模型冒充完整接入。真实 PAD 接入依赖这些信息，不能报告该部分已完成。

原始设计只包含少量普通 DFF 和组合逻辑，以及接口预留；不预置 Scan、EDT、Wrapper、IJTAG、TAP 或 Boundary Cell。预留信号名称不意味着已实现协议或插入链路。

按需求交付 RTL、文件清单、测试平台和 遵循目标工程已确认解释器与运行器约束的 Python 验证入口。复用真实 HDL 工具的已确认命令，检查层级、方向、复位、时序行为和无未声明单元；检查不得代替实际仿真。未安装仿真器或缺 PAD 模型时标注哪些验证未运行，禁止给出伪成功输出。

只有用户明确要求时扩展相应 DFT 特征；先读取该工具/版本的真实文档和目标库，保留前一阶段输入与结果。无 Sailor 资料时不猜命令、不宣称插入成功。扩展顺序与信号含义见参考规范。

可自动选择，也可 `/skill:generate-dft-circuit <工程路径与需求>` 显式调用；通常不必手动指定。
